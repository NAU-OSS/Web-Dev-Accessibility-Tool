## How to Report a Bug

If you find a bug or unexpected behavior, please check the existing issues first. If it is new, open a new issue and include:

* **Clear Title:** A brief summary of the issue.
* **Steps to Reproduce:** Step-by-step instructions to recreate the bug.
* **Expected vs Actual Behavior:** What should have happened vs what actually happened.
* **Environment Details:** Your operating system, language/framework version, and package version.
* **Chicken:** Good first issues should be tagged with "Chicken".

We love new ideas! To propose a feature, please open an issue and provide:

* **The Problem:** Describe the problem this feature solves.
* **The Solution:** Explain your proposed solution and how it works.
* **Alternatives:** Mention any alternative solutions you considered.

## How to Submit Changes

Follow these steps to contribute code or documentation changes:

1. **Fork the repository** to your own GitHub account.
2. **Clone the fork** to your local machine.
3. **Create a new branch** using a descriptive name (`git checkout -b feature/your-feature-name`).
4. **Make your changes** and ensure your code follows our style guidelines.
5. **Run existing tests** and add new tests if applicable.
6. **Commit your changes** with a clear message (`git commit -m "Add feature X"`).
7. **Push to your branch** (`git push origin feature/your-feature-name`).
8. **Open a Pull Request (PR)** against our `main` or `development` branch.

---

## Style Guide

To keep the codebase clean, please follow these guidelines:

* **Code Formatting:** Run the project linter/formatter before committing (e.g., `npm run lint` or `black .`).
* **Documentation:** Update relevant README files, inline comments, or docs for any API changes.
* **Commit Messages:** Use clear, imperative verbs (e.g., "Fix bug" instead of "Fixed bug").
